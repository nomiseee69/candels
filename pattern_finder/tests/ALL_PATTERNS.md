# Finder Candles · проверка 17 семейств

Исходная версия — `a6bc801`. Порядок и названия семейств взяты из `catalog.ALL_PATTERNS`. Проверка охватывает прямой приём фото, поиск на историческом срезе через `scanner.scan_user`, точное направление, место находки и визуальное сходство. Настройки одинаковы для обеих версий: без персонального обучения и фильтра силы, все FVG, без ограничения на эталонные OB. Для фото обязательны существующие пороги. Сеть, база пользователей и отправка сообщений в измерениях не участвуют.

На независимых 50 участках число фото с ожидаемым вариантом выросло с **41 до 43**, а возврат размеченного места по его изображению — **с 28 до 36**. Все прежние успешные локализации сохранились. При запросе по снимку **другой монеты** результат остался **6 из 35** на одних и тех же фото и свечах. Ещё пять запросов стали возможны благодаря распознаванию дополнительных эталонов; новых локализаций в них нет. Дополнительная библиотека из прежних фото дала **2 из 25** на одинаковых запросах обеих версий и **2 из 30** при расширении числа доступных запросов. На монотонном рыночном контроле эта библиотека не вернула карточек.

На отрицательных изображениях ложные предложения сократились с **16 до 0** на 97 монотонных контролях и **с 7 до 0** на 34 реальных отрицательных фото. Все 97 коротких кадров получили отказ в обеих версиях. На прежних 127 изображениях изменились три ответа: один флаг и один боковик в двух оформлениях перешли из отказа в ожидаемое предложение. Шесть внешних ADA/USD графиков с индикаторами получили отказ в обеих версиях.

### Визуальная сверка

Слева — исходный скриншот, справа — свечи фактически возвращённого участка. Оранжевая полоса указывает границы находки. При наличии совпадения на другом активе показан первый такой результат в фиксированном порядке, иначе — первый возврат исходного участка. Когда выдачи нет, правая половина пуста. Для EQH / EQL отдельно подписан более поздний момент подтверждения.

- У M на ADA совпадают две вершины и падение между ними. У кандидата обратной ГиП на LTC бот воспроизвёл цену, но два отчётливых плеча визуально спорны. Это пример высокой оценки контура при неточной метке семейства. На паре треугольников SOL/LTC рисунок сходится, но путь цены внутри границ различается. [W/M, ГиП, треугольник и клин](all_patterns_pairs_1.jpg)
- У флага и вымпела на ADA видны импульс и короткая консолидация. В паре каналов ETH/DOGE совпадает восходящее направление, но у DOGE подъём более ступенчатый. У Order Block локализованной карточки в основном фотоопыте нет. [Флаг, вымпел, канал, FVG и блоки](all_patterns_pairs_2.jpg)
- На BOS и CHoCH возвращён участок с выходом за уровень. У Mitigation совпадение цен на собственном участке оставляет открытым вопрос классификации блока. У Range сопоставляются колебания внутри интервала до последующего падения, показанного на исходном фото. [Mitigation, структура, ликвидность и Range](all_patterns_pairs_3.jpg)

## Что измерено

Дополнительные источники изображений для ручной сверки перечислены ниже. Публикации с разметкой автора оставлены ссылками: ни подпись, ни прогноз автора не использовались как подтверждение класса. В численные результаты включены только изображения, на которых выполнен прогон.

[Графики Питера Брандта](https://www.peterlbrandt.com/wp-content/uploads/2023/06/Bitcoin-A-Remarkable-Case-Study-in-Classical-Charting-Principles.pdf) · [Вымпел на BTCUSD, Scott Melker](https://www.tradingview.com/chart/BTCUSD/phghRpjT-Bitcoin-Consolidating-In-A-Bull-Pennant/)
- Свечные графики BTCUSDT с примерами Order Block, Breaker и Mitigation. Для переноса авторских меток в тест нужны независимо установленные момент формирования и первый ретест. [Order Block](https://www.tradingview.com/chart/BTCUSDT/ovh1CgYr-Market-Concepts-Lesson-01-What-Order-Blocks-Are/) · [Breaker Block](https://www.tradingview.com/chart/BTCUSDT/GF9ddICw-Market-Concepts-Lesson-05-Breaker-Blocks/) · [Mitigation Block](https://es.tradingview.com/chart/BTCUSDT.P/zcte3DjS-mitigation-block-mehanika-zaschity-kapitala/)
- Многоэлементная разметка структуры BTCUSDT пригодна для изучения неоднозначности цели. Для утверждения конкретного направления и места нужна привязка к соответствующим OHLC. [Разбор BTCUSDT, tradersboat](https://www.tradingview.com/chart/BTCUSDT/QkFac0K4-Chart-Breakdown-Smart-Money-Concept-in-Action/)

**Фото** засчитывается, если целевой тип и размеченные направление и подтип присутствуют среди предложений. Наличие среди нескольких вариантов не приравнивается к уверенному единственному ответу. В реестре сохранён полный список вариантов. **Поиск своего участка** начинается с этого фото и получает историю лишь до конечной свечи. Если распознавание не предложило цель, весь путь считается пропуском. Для короткого события допустима погрешность в четыре свечи начала. Для протяжённой фигуры требуется пересечение не менее половины объединения интервалов. Это проверка воспроизводимости места, а не способности найти новый аналог.

**Перенос** использует первый доступный фотоэталон с таким же подтипом и направлением из раздела разработки. Сканируется другой актив на отложенном периоде. Реестр различает отсутствие эталона, пустой ответ и выдачу другого участка. Для дополнительного сравнения использована отдельная библиотека из старых 127 картинок. Критерий оценивает возврат отмеченного места. Другой участок может быть пригоден, его нельзя автоматически учитывать как ложное совпадение. Опыт не сравнивает ранги всей криптобиржи.

**Контур** сравнивает реконструированные из пикселей high, low и close исходной фигуры с OHLC найденного участка. В обеих последовательностях цена нормируется по общему диапазону, время приводится к 32 точкам, из единицы вычитается средняя абсолютная разница. Это отдельная измерительная функция, она не использует оценку сходства сканера. У короткой тройки FVG и длительного боковика этот показатель имеет разный смысл. По нему нельзя оценить наличие импульсного объёма, правильность класса SMC или вероятность прибыльной сделки. На нескольких близких по виду участках он может быть высоким. В таблице нет оценки при отсутствии выдачи.

## Где останавливается перенос

На отложенных монетах максимальные корреляции структурно допустимых окон с фото M составили −0,017…0,484, ГиП — −0,538…−0,054, обратной ГиП — −0,130…0,340. Минимум поиска форм равен 0,85. Такой разброс при совпадении имени объясняет, почему исправление границ вернуло свои участки и не увеличило число независимых аналогов.

Для флагов сходство на трёх целевых участках было 0,252–0,503, для FVG — 0,318–0,514, для Breaker Block — 0,163–0,300, для единственного обеспеченного эталоном Mitigation Block — 0,450. У BOS получено 0,210–0,404, у CHoCH — 0,206–0,384, у Range — 0,285–0,544. На этих участках решающим ограничением оказался порог сходства 0,60. В одном пропущенном канале необязательный фильтр отключили для диагностики: сходство было 0,52. У одного пропущенного симметричного треугольника — 0,57; на другом треугольнике живой детектор не вернул карточку даже без фотофильтра. Для двойного дна, вымпела и Order Block в основной библиотеке не было нужного сочетания типа и направления для этих контрольных срезов.

У пропущенного бычьего флага сходство **разметки со свечами на самом фото** составило 0,610 при минимуме 0,70. Для Order Block и Mitigation Block такие оценки составили 0,348 и 0,308. Это отдельная стадия, она предшествует поиску на рынке. В реестре `filter_diagnostics` сохранены данные всех 50 отложенных участков: реконструированные свечи и линии при отказе, рыночный победитель без порога сходства, оценка у размеченного места или максимальная корреляция прошедшей проверку формы. Для пересмотра порогов нужны пары разных рынков с независимыми оценками похожести и трудными отрицательными примерами того же направления.

## Повторение

На исходном снимке прошли 105 существующих проверок pytest. После проверки нарисованных окон прошли 27 целевых тестов, после проверки свингов — 111, после изменения сравнения W/M и ГиП — 113, в окончательной версии — 113. В этих запусках падений нет. 14 модулей исходного снимка сверены с Git-объектами `a6bc801`, а финального снимка — с рабочей копией.

В тесте своего участка скриншот структуры может включать до семи свечей после отмеченного события; рыночному сканеру они недоступны. У фигур W/M и ГиП правый край изображения совпадает с концом окна. Исторические окна отобраны ретроспективно по наличию структуры. По этим результатам нельзя оценивать качество прогнозов или частоту случайных алертов во всём рынке.

Использовать одно окружение и отдельные снимки исходного кода. Первый аргумент после действия — каталог версии с исходными модулями и `tests/samples`. Аргумент ORIGINAL — кэш предыдущего `extended_charts`, FRESH — шесть файлов ADA/DOGE/LTC в формате Coinbase, CASES — локальный каталог рендеров. `prepare` запускается один раз на исходной версии, все `replay` проверяют SHA-256. Во время измерений код работает во временном каталоге. Исходные фото и исторические свечи предыдущих этапов не перезаписываются.

```text
python tests/all_patterns_eval.py prepare BASE ORIGINAL FRESH CASES unused.json
python tests/all_patterns_eval.py replay ENGINE ORIGINAL FRESH CASES results.json
python tests/all_patterns_eval.py controls ENGINE ORIGINAL FRESH CASES real-negatives.json
python tests/all_patterns_eval.py levels ENGINE ORIGINAL FRESH CASES confirmation.json
python tests/all_patterns_eval.py bank ENGINE ORIGINAL FRESH CASES legacy-transfer.json
python tests/all_patterns_eval.py diagnose ENGINE ORIGINAL FRESH CASES diagnostics.json
```

### Последовательные прогоны

«Лишние» — число фото с любым предложением на монотонной отрицательной цене. «Короткие» — число предложений на семисвечных кадрах. Для каждого этапа порядок случаев, фото и свечи зафиксированы.

| Версия | Выборка | Фото | Своё место | Перенос | Лишние | Короткие |
|---|---|---:|---:|---:|---:|---:|
| base | dev | 37 | 24 | 0/0 | 8 | 0 |
| base | holdout | 41 | 28 | 6/35 | 8 | 0 |
| group1 | dev | 41 | 28 | 0/0 | 8 | 0 |
| group1 | holdout | 43 | 30 | 6/40 | 8 | 0 |
| group2 | dev | 41 | 28 | 0/0 | 0 | 0 |

| final | dev | 41 | 34 | 0/0 | 0 | 0 |
| final | holdout | 43 | 36 | 6/40 | 0 | 0 |

base — исходное состояние; group1 — проверка нарисованных окон; group2 — свинги под двумя линиями; group3 — сопоставление по опорным точкам W/M и ГиП; final — исключение рисунка, целиком вынесенного за цену.

В реестре строки case включают исходные данные каждого изображения и состояния на тех этапах, где ответ изменился. При отсутствии ключа этапа действует предыдущее состояние. Другие типы строк содержат реальные отрицательные кадры, отдельную библиотеку фотоэталонов, проверку подтверждения свинга, внешние источники и изменения прежнего набора.
