# Поиск по фото на фиксированных исторических свечах

Сравнение воспроизводит вызовы `rank` из `extended_charts.py`. Для обеих исходных версий скрипт проверяет все шесть хешей рыночных файлов и полное совпадение карточек, порядка и оценок с `extended_charts_results.jsonl`. Четыре исходных изображения используются без изменений. В контрольном периоде использованы другие свечи, эталоны те же. Отдельный повтор распознавания всех 127 изображений дал те же записи, включая варианты ответа и причины отказа.

## Причины исчезновения пригодных карточек

Номер начала считается с нуля. Срез N включает первые N свечей. Все шесть исчезнувших карточек имели допустимый подтип и оценку детектора не ниже 0,85. Все шесть в версии `8a9b3f5` остановил порог сходства 0,60 до группировки. Ни одна из них не дошла до пользовательских фильтров. В двух срезах BTC H1 повторно видна одна и та же зона.

|---|---|---:|---:|---|---|
| Медвежий FVG | BTC H1, 200 | 160 | 1,00 | 0,3364 → 0,6920 | Возвращён |
| Медвежий FVG | BTC H1, 240 | 160 | 1,00 | 0,3364 → 0,6920 | Возвращён |
| Медвежий FVG | BTC D1, 240 | 227 | 1,00 | 0,4439 → 0,8051 | Возвращён |
| Симметричный треугольник | SOL H1, 160 | 48 / 135 | 1,00 / 0,90 | 0,3767 → 0,5504 / 0,3192 → 0,7841 | Карточка восстановлена по более короткой фигуре, длинное окно осталось ниже порога |

| Нисходящий канал | BTC H1, 200 | 173 | 0,90 | 0,5299 → 0,5901 | Ниже порога |

**FVG.** Третья свеча на эталоне обрезана нижним краем. Силуэт до и после разрыва получал вес 0,35, в том числе за движение, которого не видно. В числовую часть также входила нулевая «значимость» при отсутствии объёма и подтверждённого предшествующего минимума. У BTC H1 числовая и визуальная части были 0,4613 и 0,1045, у BTC D1 — 0,5368 и 0,2713. Исправление использует ширину разрыва и тело импульса, когда эти признаки видны. Обрезанное тело самого импульса служит причиной отказа. Видимые признаки слабого импульса или несостоявшегося пробоя сохраняются. Исходные пять оставшихся пропусков происходят ещё в детекторе: все размеченные разрывы на каждом таком рынке меньше 0,5 ATR. В контрольном периоде семь из двенадцати пропущены по этой причине, пять прошли детектор, но не набрали 0,60 сходства.

**Линейные фигуры.** На эталоне треугольника две линии занимают отрезки x=220…513 и 318…462, а восстановленная цена заканчивается на x=377. Прежний отпечаток сравнивал геометрию на 220…513, включая пересечение продолжений, с ценой на другом отрезке. Исправление измеряет обе границы и движение цены в общем наблюдаемом диапазоне 318…377, а на рынке применяет тот же принцип. Все четыре остальные окна независимого набора с подходящим подтипом (три треугольника и один канал) видны в реестре. Канал прошёл, три треугольника остались за порогом.

**Выбор победителя.** При фото-поиске FVG и линейных фигур обязательный подтип и действующие минимумы проверяются до выбора лучшего варианта в монете. Регрессии отдельно моделируют вытеснение допустимой зоны противоположной и выбор между окнами разных подтипов. Это дополнительная защита, признаков потери исходных шести карточек при группировке не найдено.

## Как читать сравнение

В сохранённом сценарии качество установлено в `off`, обучение выключено, режим FVG — «все». Старый поиск воспроизведён с исходной настройкой `similar_only=False`. Фото-поиск сам требует 0,60. В предыдущем расширенном тесте включение «только похожие» у старой версии воспроизводило исходную строгую выдачу. Для сопоставления версий сохранены настройки и порядок рынков предыдущего опыта.

На каждый эталон приходится шесть запросов по трём монетам. Единица полноты — рынок на конкретном срезе с хотя бы одним подходящим кандидатом. Во время подсчёта находок FVG сверяются начало и направление фактически выданной зоны с независимо вычисленным списком свежих или близких, ещё не отработанных трёхсвечных разрывов. У линий независимой экспертной разметки нет. Критерий пригодности здесь — активное окно именно нужного подтипа с оценкой детектора от 0,85. Поэтому статистика ошибок линейных фигур оценивает соблюдение этого критерия, а не визуальное сходство по оценке человека.

В реестре `photo_selection_results.jsonl` строки `source` содержат хеши входных файлов. Для каждого запроса строка `query` содержит список кандидатов по рынкам, компоненты сходства FVG, оценки каждого активного линейного окна, победителя детектора, результат после оценки и сходства, выход пользовательских фильтров, вход группировки и финальные карточки всех трёх версий. Отсутствующая оценка означает, что стадия её не вычисляла. У FVG после отсечения силуэта значение `visual` нужно читать совместно с итогом: функция сравнения отпечатка без окна использует только числовые признаки.

Исходный период начинается 01.06.2024 для H1 и 01.01.2023 для D1. Контрольный период начинается 01.03.2025 для H1 и 01.01.2024 для D1. Для каждой пары BTC-USD, ETH-USD, SOL-USD взяты первые 240 последовательных свечей, срезы 160, 200 и 240. Источник — [публичные исторические свечи Coinbase Exchange](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-candles). Для контрольных файлов параметры `granularity` равны 3600 или 86400, верхние границы запросов 11.03.2025 и 28.08.2024 в 00:00 UTC. Замеры выполнялись из локальных файлов.

Для повтора запускайте каждую версию отдельным процессом: `python tests/photo_selection_eval.py ENGINE ORIGINAL_CACHE HOLDOUT_CACHE OUTPUT.json`. ENGINE — каталог исходников соответствующей версии (названия каталогов исходных версий совпадают с короткими хешами). ORIGINAL_CACHE — исходный кэш extended_charts. HOLDOUT_CACHE — каталог с шестью контрольными файлами вида BTC-USD-1h.json в формате ответа Coinbase. Сравнение использует временный рабочий каталог.

## Ограничения и следующая проверка

Интервалы разделены по времени внутри каждого таймфрейма. Контрольный D1 включает даты исходного H1, и в обоих периодах использованы те же три актива. Контроль проверяет перенос на другие свечи при фиксированном фото. Перенос на новые рыночные режимы, активы и новые изображения требует отдельной проверки.

Эти данные позволяют проверить возврат конкретных случаев и контроль подтипа. Срезы одного рынка зависимы, на семью приходится один фотоэталон и максимум три позиции в выдаче. Для изменения порога или вывода о качестве порядка нужна слепая разметка пар «эталон — рыночное окно», включая внешне близкие отрицательные примеры того же направления. Предлагаемый следующий опыт — минимум 100 положительных и 100 трудных отрицательных пар на семейство, разделение по исходному изображению, рынку и периоду, выбор порога на части для разработки и единственная проверка на отложенной части. Сравнить полноту при прежней доле ложных срабатываний, долю пустых запросов и nDCG@5 по градуированной человеческой разметке. Интервалы неопределённости считать с группировкой по исходному сюжету.
