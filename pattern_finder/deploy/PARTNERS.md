# Finder Candles Partners · локальная версия ручных выплат

## Контур учёта

| Событие | Записи и результат |
|---|---|
| Первый /start с fc-кодом | Случайная постоянная ссылка → одно закрепление нового пользователя в SQLite |
| Первая успешная покупка за Stars | Pro и оплата фиксируются вместе. Партнёрская запись выполняется в savepoint. При ошибке она восстанавливается из платежа на очередной сверке |
| Сверка | Подтверждённое поступление по журналу Stars + подтверждённый вывод Fragment + входящий официальный USDT + запись источника и комиссий → обеспеченное начисление |
| Заявка | Проверен остаток кошелька и журнал → атомарный перенос из доступного в резерв |
| Одобрение и отправка | Одобрение → подготовка → сверка Stars и резерва → одноразовое разрешение → ручная отправка → ввод TXID |
| Подтверждение | Проверка всей цепочки на TON Mainnet → проводка оплаты с уникальным корневым TXID и TXID зачисления |
| Возврат покупки | До разрешения перевода заявка освобождает резерв. После разрешения резерв остаётся замороженным, администратор получает уведомление. Непокрытая сумма учитывается в долге |

Суммы хранятся в микро-USDT. Округление вниз делается один раз для каждого начисления по формуле: чистый реализованный USDT × Stars покупки × ставка / Stars подтверждённого вывода. Выводится ровно сумма заявки. TON на сетевые комиссии предоставляет владелец. Справочный курс фиксируется с датой и источником через /partners rate и влияет только на предварительную оценку. Фактический курс хранится как дробь между чистыми USDT и Stars из конкретной сверки.

Период ожидания минимум 21 день. После него начисление ждёт отдельного подтверждения обеспечения. Доступная сумма проверяется против актуального USDT-остатка и учтённых пополнений. Если данные TON недоступны или баланс меньше обязательств, Mini App показывает сумму на сверке. Локальный резерв остаётся зарезервированным.

## Источники и ограничения

- Нативные настройки и старые начисления смотрите в профиле приложения и журнале Stars. Доступ владельца к этим экранам в рамках разработки не использовался. Завершите нативную программу вручную и проверьте дату завершения. Telegram продолжает начисления для части уже приведённых пользователей в течение их исходного периода. Для перехода предусмотрена пауза 32 дня от подтверждённого завершения месячной программы. Если ранее срок был дольше месяца, выдержите его полностью отдельным решением. [Партнёрская программа Telegram](https://telegram.org/tos/affiliate-program)
- Оплата подписок внутри Telegram остаётся в Stars. USDT используется для партнёрского вознаграждения. Уточните условия программы и налоговые требования своей юрисдикции перед включением. [Правила оплаты Stars](https://core.telegram.org/bots/payments-stars) · [Условия для разработчиков](https://telegram.org/tos/bot-developers)
- Сверка импортирует только подтверждённые выводы Fragment из официального журнала. Владелец вручную сопоставляет подтверждённый Fragment ID, полученный TON и конвертацию с входящим переводом USDT. Приложение проверяет факт вывода Stars и поступление USDT, но не может установить происхождение конвертированных средств без сверки выписки владельцем. [Журнал Stars](https://core.telegram.org/bots/api#getstartransactions) · [Вознаграждение за Stars](https://core.telegram.org/api/stars)
- Поддерживаются активные V4R2 и V5R1 в TON Mainnet. Для других типов кошельков подключение завершается отказом. Backend сверяет StateInit и адрес, ключ в StateInit и в Mainnet, домен, timestamp и одноразовый challenge. Манифест доступен без авторизации, с PNG-иконкой. [TON Proof](https://docs.ton.org/applications/ton-connect/how-to/ton-proof) · [Стандартные кошельки](https://docs.ton.org/contracts/standard/wallets/history)
- Верификатор доверяет данным закреплённого Mainnet-индексатора TonAPI через HTTPS. Проверяются официальный мастер Tether, точность, связанные жетон-кошельки и успешное зачисление в полном trace. Хеши исходящих сообщений берутся из BOC транзакций, поскольку trace может вернуть пустой список `out_msgs`. Проверка прошла на публичном переводе без участия проекта. Сложные пакетные переводы следует исключить из ручного процесса. Сервер не подписывает и не отправляет переводы. [Tether USDT](https://tether.to/en/supported-protocols/) · [Цепочки транзакций TON](https://docs.tonconsole.com/academy/transaction-tracking/) · [Проверенный перевод](https://tonviewer.com/transaction/4fd0f6affccb4f71b37b97ea9e4097fbf3958207ad520379df3866a4bc460f36)

## Настройка тестового окружения

1. Используй отдельные Telegram-учётные данные и временную SQLite либо безопасную копию схемы без реальных данных. Установи зависимости проекта. Проверь /health, получение манифеста и его PNG через HTTPS. Подключи тестовую Mini App и проверь доказательство владения активным кошельком. Публичный URL на действующей версии ответил HTTP 404 до развёртывания этого кода.
2. Для тестов настройки кошелька используй REFERRAL_TEST_MODE=1. В этом режиме покупка не создаёт реального начисления, заявки и обеспечение заблокированы. Автоматические проверки подменяют TON и Telegram. Для Mainnet-пилота нужна отдельная сверка из полученных выписок.
3. Для ранней регистрации включи `REFERRALS_ENABLED=1` и `REFERRAL_EARLY_REGISTRATION=1`. Партнёры смогут получить ссылки заранее. Атрибуция включается после подтверждённого закрытия нативной программы, записи её UTC-даты в `REFERRAL_NATIVE_ENDED_AT` и отключения `MINI_APP_AFFILIATE_ACTIVE`. Переходы до открытия атрибуции не засчитываются задним числом. Первые покупки после действительной атрибуции учитываются предварительно. Обеспечение и выплаты открываются после защитного периода не менее 32 дней и сверки конкретной покупки. Если предыдущая программа действовала дольше месяца, отключи обеспечение и вывод до конца всего применимого срока.
4. Используй один адрес как `TON_TREASURY_ADDRESS` и `TON_PAYOUT_SOURCE_ADDRESS`. Укажи отдельный публичный `TON_SETTLEMENT_SOURCE_ADDRESS`. Адрес резерва закрепляется в базе при первом учёте средств. Для смены нужны остановка выплат и миграция обязательств. После приёмки включи `REFERRAL_PAYOUTS_ENABLED`. Регистрация, атрибуция, обеспечение и вывод управляются независимо в `/admin`. Остановка вывода сохраняет начисления по действующим привязкам.

## Сверка и выплаты

1. Бот сверяет журнал Stars каждые две минуты. `/partners sync` запускает сверку вручную. `/partners reconciliation` показывает импорты и время последней успешной сверки. Для подготовки требуется полная сверка в пределах пяти минут, а прямо перед выдачей разрешения сверка выполняется снова. Неполная пагинация, изменившаяся первая страница или сбой Telegram блокируют операцию. Лимит по умолчанию — 40 страниц по 100 записей, настраивается через `REFERRAL_STARS_MAX_PAGES` до 200. При исчерпании лимита или срока сверки выплаты остаются заблокированными до успешной полной сверки. Для диагностики доступен `/root/candels/.venv/bin/python mini_star_audit.py --offset 0 --fragment` из `/root/candels/pattern_finder`. Ручной импорт страницы не считается полной сверкой.
2. После получения TON и конвертации переведи USDT с настроенного адреса пополнения на адрес резерва. Вызови /partners batch TXID FRAGMENT_ID STARS TON_NANO COST_USDT CHARGE[,CHARGE]. COST_USDT — дополнительные подтверждённые расходы, которые ещё не вычтены из поступления. Используй 0, если сумма пополнения уже чистая. /partners topup TXID причина учитывает пополнение резерва без начисления комиссии. Для одной транзакции выбирай только один из этих вариантов.
3. Открой `/admin` → «Партнёрская программа». Одобри заявку, подготовь перевод и запроси одноразовое разрешение. Для крупной выплаты введи её точную сумму. После повторной сверки Stars, рисков, долга и резерва бот выдаёт разрешение один раз. Переводи только после получения разрешения и сразу запиши TXID. Повтори проверку при задержке индексатора. Возврат возможен между выдачей разрешения и ручным переводом. Перед подтверждением в кошельке проверь сообщения бота и операции кошелька.
4. Ошибочную подготовку можно вернуть в очередь одобренных до выдачи разрешения. Резерв при этом сохраняется. После выдачи разрешения, включая сбой доставки ответа, и для заявок, подготовленных старой версией, перевод мог начаться. Сверь кошелёк и фактический перевод. Один лишь ответ «TXID не найден» не освобождает резерв и не даёт нового разрешения. Ошибочный TXID можно заменить в карточке или через `/partners replace НОМЕР НОВЫЙ_TXID причина` и `/partners confirm КОД`, только если новый перевод подтверждается. История вводов и попыток сохраняется в аудите. Если судьбу перевода нельзя установить, оставь резерв заблокированным до ручной сверки.

## Обновление HOSTKEY после согласования

Следуй инструкции обновления и отката. До публикации сделай согласованную резервную копию SQLite, `.env`, `ai.json`, `brain.json` и каталога `patterns`. Проверь через `systemctl cat pattern-finder finder-mini-app`, что обе службы используют один `WorkingDirectory=/root/candels/pattern_finder`, один `EnvironmentFile` для реферальных настроек и одну SQLite. Проверь, что старые drop-in-файлы не переопределяют эти значения. [Инструкция Mini App](MINI_APP.md)

После согласованной публикации проверенного коммита и резервного копирования:

```bash
set -euo pipefail
cd /root/candels
git fetch origin main
git diff --quiet HEAD origin/main -- pattern_finder/ai.json pattern_finder/brain.json
git merge --ff-only origin/main
cd pattern_finder
/root/candels/.venv/bin/python -m pip install -r requirements.txt
systemctl restart pattern-finder finder-mini-app
curl --fail http://127.0.0.1:8765/health
```

В существующем HTTPS-блоке Nginx добавь или обнови только `location = /api/partners/verify` с лимитом тела 24k и текущим прокси на Mini App. Сохрани действующий домен, TLS и остальную конфигурацию. Проверь `nginx -t` перед перечитыванием. Первое обновление выполняй с выключенными регистрацией и выплатами. Старую копию базы можно восстановить только после сверки всех последующих оплат, возвратов и переводов.
