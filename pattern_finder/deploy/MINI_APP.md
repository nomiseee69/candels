# Finder Candles Mini App

## Подготовка на HOSTKEY

1. Создайте DNS-запись для выбранного поддомена. В примерах используется `mini.example.invalid`. Получите сертификат TLS существующим способом для этого сервера.
2. Перед обновлением сделайте согласованную резервную копию базы средствами SQLite или существующей командой бота. Убедитесь, что рабочая база уже перенесена из JSON в SQLite, и проверьте запуск на копии базы. Используйте один процесс бота.
3. Разместите backend в рабочем каталоге той же установки, что и служба `pattern-finder`. Шаблон рассчитан на текущую установку в /root. Для выделенного системного пользователя перенесите приложение и базу в доступный ему каталог отдельным изменением. Оба процесса должны видеть одну и ту же локальную базу и файлы WAL/SHM. Backend пишет заказы и данные сверки, выдачу Pro выполняет бот. Статус в Mini App читается без активации пробного периода. Пробный период по-прежнему оформляется при входе через чат. Это исключает параллельную перезапись пользовательских настроек двумя приложениями.
4. Укажите `MINI_APP_URL=https://<ваш-поддомен>/` в закрытом `.env` проекта. Установите права 0600 на файл, используйте текущий токен Telegram и выделенного пользователя службы. Токен не нужен Nginx. Шаблон службы слушает через backend только 127.0.0.1:8765.
5. Подставьте домен и пути сертификата в шаблон Nginx. Проверьте конфигурацию через `nginx -t`, перечитайте её и запустите новую службу. Проверьте выдачу HTML по HTTPS и отказ API без initData. Основной бот получает Telegram Updates как прежде. Mini App не запускает второй опрос.
6. Для отката установите `MINI_APP_PROFILE_ENABLED=0` и перезапустите бота. Это возвращает прежний экран покупки, сохраняя обработку уже выпущенных счетов и продлений. Остановите веб-службу и удалите маршрут Nginx. Если счета Mini App уже выпускались, сохраните новую обработку платежей в основном боте до окончания связанных подписок. Возврат старой SQLite из копии требует отдельной сверки всех платежей после снимка.

## BotFather и партнёрская программа

1. В аккаунте владельца откройте `@BotFather` → `/mybots` → `@findercandles_bot` → настройки бота → Main Mini App. Укажите проверенный HTTPS URL и оформите профиль приложения. После установки MINI_APP_PROFILE_ENABLED=1 кнопка подписки в личном чате открывает этот URL. Старые команды и счета продолжают работать. [Telegram Mini Apps](https://core.telegram.org/bots/webapps)
2. После отдельного решения владельца откройте профиль Mini App в Telegram → «Редактировать» → «Партнёрская программа». Выберите 10% и один месяц, если этот период доступен в интерфейсе владельца. Параметр API выражается в месяцах. Нативная программа учитывает подходящие покупки в течение выбранного периода и может учитывать несколько покупок. Telegram контролирует доступность настройки. [Партнёрский API](https://core.telegram.org/api/bots/referrals) · [Руководство Telegram](https://telegram.org/tour/affiliate-programs)
3. Партнёр открывает «Настройки» → «Мои звёзды» → «Заработать звёзды», выбирает Finder Candles, если программа доступна, и выбирает баланс зачисления. Ссылка и статистика доступны в Telegram. Бот не генерирует партнёрских ссылок. Telegram удерживает начисления 21 день и может списать их при возврате. [Условия](https://telegram.org/tos/affiliate-program)

## Оплата и сверка

Сервер проверяет HMAC подписанных initData и срок 15 минут. Суммы и условия счета определяет сервер. Обычные счета привязаны к пользователю, тарифу и сумме, первоначальный checkout истекает через 15 минут. Скидочные счета используют существующий одноразовый механизм. Месячный стандартный счёт продлевается каждые 30 дней, остальные разовые. Внутри Mini App открывается Telegram openInvoice. Доступ выдаётся в транзакции SQLite только по successful_payment. После закрытия счета интерфейс опрашивает сервер по конкретному счёту. При истечении подписи приложение нужно открыть заново. [Документация оплаты Stars](https://core.telegram.org/bots/payments-stars)

Администратор может выполнить `python mini_star_audit.py --offset 0` с тем же окружением и рабочим каталогом. Одна команда читает одну страницу из 100 записей. Для остальных страниц увеличивайте offset. Сверка сопоставляет charge ID и покупателя с подтверждённой локальной оплатой. В журнале отдельно хранятся сумма движения Stars Telegram, сумма комиссии из AffiliateInfo при наличии и события возврата. Сумма исходной покупки берётся из существующей записи платежа. Отсутствующая комиссия остаётся неизвестной. Сверка не меняет подписки. [Bot API](https://core.telegram.org/bots/api#getstartransactions) · [AffiliateInfo](https://core.telegram.org/bots/api#affiliateinfo)

## Остаётся проверить в Telegram

- Запуск Main Mini App на Android и iOS и реальную авторизацию через Telegram.
- Открытие обычного, годового и скидочного счёта внутри приложения, автопродление и возврат на отдельном тестовом боте.
- Первое открытие приложения новым пользователем по нативной ссылке, одну контролируемую оплату и две фактические записи о распределении. Суммы 450/50 являются ожидаемым сценарием для покупки за 500 Stars при ставке 10%, пока нет подтверждения журнала Telegram.

## Порядок запуска владельцем

На компьютере проверьте локальную ветку и тесты. После разрешения на публикацию выполните в PowerShell из репозитория:

```powershell
git status --short --branch
git switch main
if ($LASTEXITCODE) { throw "switch" }
git merge --ff-only codex/native-mini-app
if ($LASTEXITCODE) { throw "merge" }
git push origin main
if ($LASTEXITCODE) { throw "push" }
```

На сервере зайдите через `ssh root@<IP-HOSTKEY>`. Выполните резервную копию перед обновлением. Команда SQLite создаёт согласованный снимок открытой базы в режиме WAL.

```bash
set -euo pipefail
cd /root/candels
umask 077
backup="/root/finder-backup-$(date +%Y%m%d-%H%M%S)"
mkdir "$backup"
cd pattern_finder
.venv/bin/python -c 'import sqlite3,sys; src=sqlite3.connect("file:users.db?mode=ro",uri=True); dst=sqlite3.connect(sys.argv[1]); src.backup(dst); dst.close(); src.close()' "$backup/users.db"
cp -a .env ai.json brain.json "$backup/"
if [ -d patterns ]; then cp -a patterns "$backup/"; fi
cd ..
git rev-parse HEAD > "$backup/revision"
git fetch origin main
git diff --quiet HEAD origin/main -- pattern_finder/ai.json pattern_finder/brain.json
git merge --ff-only origin/main
```

Если проверка конфигов или fast-forward прервались, остановитесь и разберите конфликт. Рабочие настройки остаются на диске. База и фотографии лежат отдельно от кода. Если нужного файла для копирования нет, проверьте его фактический путь перед повтором.

После создания DNS A/AAAA, указывающих на HOSTKEY, проверьте, какой веб-сервер уже обслуживает порты 80/443. Для свободного сервера установите Nginx и Certbot из Ubuntu. Добавьте HTTP-виртуальный хост своего поддомена и получите сертификат через `certbot --nginx -d <ваш-поддомен>`. Если сервер уже использует HTTPS-прокси, добавьте маршрут к 127.0.0.1:8765 в нём. Сохраните правила других сайтов.

```bash
set -euo pipefail
cd /root/candels/pattern_finder
chmod 600 .env
nano .env
install -m 644 deploy/finder-mini-app.service /etc/systemd/system/finder-mini-app.service
systemctl daemon-reload
systemctl enable --now finder-mini-app
curl --fail http://127.0.0.1:8765/health
systemctl restart pattern-finder
```

В `.env` укажите HTTPS URL и оставьте `MINI_APP_PROFILE_ENABLED=0` и `MINI_APP_AFFILIATE_ACTIVE=0`. В конфигурации Nginx подставьте домен и сертификат из примера, проверьте `nginx -t` и выполните `systemctl reload nginx`. Проверьте `curl --fail https://<ваш-поддомен>/health` и отсутствие доступа к файлам `.env`, SQLite, фотографиям. Состояние службы проверяется через `systemctl status finder-mini-app`.

Далее подключите Main Mini App в BotFather. Сначала используйте отдельного тестового бота и тестовые данные для проверки входа, обычной оплаты, автопродления, скидки и возврата. С флагом профиля 0 публичная кнопка в чате скрыта. Привязка Main Mini App через BotFather сама делает приложение доступным из его профиля, поэтому на рабочем боте эту привязку делайте только когда готовы к обнаружению приложения.

Проверка реальной нативной комиссии требует активной программы Telegram. Сначала проверьте, доступна ли функция в отдельном тестовом окружении. Если она доступна только на рабочем боте, потребуется согласованное ограниченное окно запуска. Владелец включает 10% на месяц, передаёт официальную ссылку одному контролируемому партнёру и проводит одну разрешённую покупку с нового для Mini App аккаунта. Публичные ссылки и кнопку профиля включайте после сверки. Telegram может показать программу сразу после её создания и прекращает действие ссылок с задержкой. Уже закреплённые рефералы могут продолжать приносить комиссию в течение исходного периода.

Сверка владельцем из рабочего каталога:

```bash
.venv/bin/python mini_star_audit.py --offset 0 --charge '<Telegram charge ID>'
.venv/bin/python mini_star_audit.py --conflicts
```

Сверьте движение по журналу Telegram, AffiliateInfo и выбранный партнёром баланс. Месячные платежи Telegram имеют период 2 592 000 секунд. Партнёрское окно отсчитывается от нативного присоединения, а не от первой покупки. Первая покупка спустя несколько недель может попасть в остающийся период. Начисление на границе первого продления проверяется по фактическому журналу, поскольку документация не обещает особого правила для этой границы. Следите также за продлением после недостаточного баланса и подтверждённой отменой.

После успешной проверки выставьте `MINI_APP_PROFILE_ENABLED=1`. Флаг `MINI_APP_AFFILIATE_ACTIVE=1` меняет только описание на экране, его включают после проверки настроек Telegram. Перезапустите службы, проверьте вход из профиля и меню из двух кнопок.

### Конфликтующие платежи и отключение

Mini App, старые ссылки и скидки используют одну резервацию подтверждения Stars на пользователя. Она истекает через пять минут. При оплаченном доступе новая покупка доступна после его окончания. Отмена автопродления сохраняет оплаченный срок. Если Telegram не предоставляет исходное подтверждение для управления старой подпиской, используйте список подписок в клиенте Telegram. Для неоднозначных старых продлений бот сохраняет платёж для ручной сверки при обнаружении конфликта; одинаковые legacy payload не идентифицируют две ранее созданные подписки. Подтверждённые старые карточные заказы обслуживаются прежним потоком.

Для отключения верните оба флага в 0, перезапустите службы и при необходимости отключите Main Mini App в BotFather. Прекращение официальной программы выполняет владелец через профиль Mini App. При откате оставьте обработчики новых заказов и возвратов в основном боте, пока они нужны действующим подпискам.
